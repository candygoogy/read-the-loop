An agent is a loop

A language model can do one thing: read text and write more text. It can't open a file, run a test or play a game. Below, a model fixes a bug in a small game it never sees. Try the game first. The bug shows up within seconds.

The setup

You've seen this game before: a paddle at the bottom, bricks at the top, a ball bouncing between them. Here the ball falls through the right half of the paddle as if it weren't there. On the left half it bounces as it should.

What this run shows

It checked before and after

The model never saw the game. Before it changed anything, it ran the tests, and a failing test came back: . The edit came on the next call, along with a second test run in which all passed. Each of those was a round of the loop, and each result was text the harness pasted in. That's also why the rule picked this run:

It reads everything, every time

The model keeps nothing between calls. The conversation is its memory, so the harness sends all of it every time. To change lines, calls read tokens between them, of them from the cache. Chapter 3 is about the cache.

"Done" is the model's own call

Nobody tells the agent to stop. Its last reply had no request in it, so the harness stopped. The same reply says the agent checked that a fast ball can't skip past the paddle, and that check exists only as sentences in the reply. Here the tests and the fixed game back up the main claim.
