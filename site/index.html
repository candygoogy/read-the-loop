An agent is a loop

A language model can do exactly one thing: read text and write more text. It can't open a file, run a test or touch your computer. So how does it fix a bug in your code? Let's watch one do it.

Everything below is a real session, recorded on 8 November 2026 with Claude Code. No step is staged or edited.

The setup

Here's a tiny shopping cart with a bug. Twenty percent off a $50 item should cost $40. The code says it costs $10.

Three things worth noticing

1. The model starts from zero every time

The model doesn't remember the last call. The conversation is its memory, so on each call the harness sends the whole thing again from the top. Fixing one line took four calls that read tokens in total. Most of that was the same instructions, read over and over. Reading something a second time is much cheaper, because the provider keeps a copy of text it has just seen: of those tokens came from that cache. That trick, and what happens when the conversation outgrows the model, is chapter 2.

2. It finds out about your computer by being wrong

On its second call the model tried to run the tests with pytest, a popular tool that isn't installed on this computer. It couldn't have known. It only found out because the harness pasted the error back into the conversation, and on the next call it used Python's built-in test runner instead. The loop is how the model learns anything about the world outside its text.

3. "Done" is just a reply without a request

Nobody tells the agent to stop. The harness keeps looping while the model's replies contain requests. When a reply comes back that's plain text, like the summary at step 8, the loop ends. That makes "done" the model's own call, and it's why agents sometimes stop too early or say they've finished when they haven't. Chapter 7 is about those failures and the guard rails against them.
